# 图解绘制

用单文件 HTML 和内联 SVG 绘制信息准确、中文清晰、可离线打开的图解。HTML 是源文件，PNG 是确认后的导出物。

## 1. 确定内容与风格

阅读用户提供的材料；代码相关图解先核对实现。确定要解释的问题、主要对象、关系和阅读方向，区分原始事实与推断。缺少会改变图意的关键信息时提问，其余采用合理默认值。

- 指定风格时遵从用户；否则技术架构、流程默认 `blueprint`，课堂讲解、学习笔记默认 `chalkboard`。
- 首版只支持这两种风格。其他风格请求说明当前边界，让用户选择；不要把换色命名为第三种风格。
- 开始绘制前读取 [风格规范](references/styles.md) 中对应风格；以 [HTML 模板](assets/template.html) 为可运行起点，根据内容重新布局，不必沿用示例的节点数量和结构。
- 默认单张 1600×900 CSS 像素，中文文案。长内容可增高画布或拆图，保持字号可读。
- 默认输出到当前项目的 `diagram/<topic-slug>/`，已有约定或用户指定位置优先。保留已有源文件，修改时沿用原名称或另存版本。

## 2. 绘制 HTML

根据关系选择布局：架构图按职责分区，流程图写清分支条件，时序图统一时间方向，概念图把关键关系放在连线上。图解须包含实际关系或视觉解释，避免把长段文字排列成卡片后当作图。

遵循 [HTML 与导出约定](references/html-export.md)。关键做法：

- 仅有一个 `#diagram` 导出根节点；预览说明和工具栏放在外部。
- CSS、SVG、纹理和必要脚本内联，使用本地字体；打开页面不请求网络。
- 连接线先绘制，节点后绘制，文字最后绘制；按实际关系标注箭头，给文字和箭头留出间距。
- 中文使用明确的 `<tspan>` 分行，节点随文本扩宽；正文建议 22–28px。先压缩文案或调整画布，再考虑缩小字号。
- 风格通过 `data-style` 和 CSS 变量控制。粉笔纹理只作用于笔画与底纹，正文保持清晰。

## 3. 检查并交付 HTML

用实际 Skill 路径替换下列 `{baseDir}`，先运行结构与渲染检查：

```bash
node "{baseDir}/scripts/render.mjs" "<图解.html>" --check
```

使用可用的浏览器工具打开 HTML，或生成临时截图并实际查看：

```bash
node "{baseDir}/scripts/render.mjs" "<图解.html>" --output "<临时目录>/preview.png" --scale 1
```

临时截图只用于视觉检查。检查中文缺字、断行、遮挡、箭头方向、标签位置、裁切和两种风格的识别度；脚本成功不代表这些问题均已排除。有问题先修改并重新检查。

向用户提供 HTML 的可点击路径、风格和尺寸，说明“确认后导出 PNG”，随后等待明确确认。**默认不在本轮交付最终 PNG。** 用户要求修改时更新 HTML，再展示并等待确认；此前的确认不延续到修改后的版本。

用户已明确要求自动检查并导出时，可在完成视觉检查后连续执行下一步。不要将沉默、技术检查通过或用户对另一张图的确认视为本图确认。

## 4. 确认后导出 PNG

从确认的 HTML 导出，默认 2 倍分辨率；1600×900 对应 3200×1800：

```bash
node "{baseDir}/scripts/render.mjs" "<图解.html>" --output "<图解.png>" --scale 2
```

实际查看 PNG，核对其尺寸、内容与确认稿一致，再交付 HTML 和 PNG 链接。导出失败时保留 HTML，说明具体缺少的运行环境或检查错误；不要改用重新生图而改变确认稿。

导出器只依赖 Node.js 22.4+ 与本机 Chrome/Chromium/Edge，无 npm 包依赖。发现或指定浏览器的方法见 [HTML 与导出约定](references/html-export.md)。
